ARRA Oracle DNA

Five skills, five souls, and the argument that an AI persona is not a prompt — it is a pair of Markdown files you can read, fork, and version.

ARRA Oracle is the system — ψ/ memory, the arra-oracle-v3 server, the skills CLI, and a family registry of 811 — 297 humans, as of 2026-09-06. An Oracle is one instance living inside it. This deck is about how a single instance gets written down.

The thesis

A persona is not a prompt.
It is two files on disk.

Most attempts at giving an AI a personality end up as one long system prompt — unversioned, unreadable, and impossible to hand to a colleague. This archive takes the opposite position. Every Oracle here is split in two: a skill file that says what to do, and a resonance file that says who is doing it.

The split is the whole idea. Mechanics change often — new steps, new triggers, new tools. Identity changes slowly and deliberately, and gets a dated log entry when it does. Keeping them in separate files means you can rewrite a workflow without disturbing a voice, and deepen a character without touching a single step.

Skill = mechanics (trigger + steps) · Resonance = soul (identity + DNA + voice)

— Pattern 01, from the archive's own reading notes

Architecture

Three layers, three directories.

The numbering is real: this is a pipeline. A request enters at the skill, is performed by the identity the resonance describes, and leaves a trace in memory that the next session reads back.

Skill · วิธีทำงาน

01

Trigger words, steps, prompts. The mechanics that turn an intention into a workflow you can actually run.

.claude/skills/{name}/SKILL.md

Resonance · ตัวตน

02

Identity, influences, voice, values. The personality behind the work — and the reason two Oracles running the same steps don't sound the same.

ψ/memory/resonance/{name}.md

Memory · ความทรงจำ

03

Persistent context, retrospectives, learnings. The record of what changed, so an Oracle can tell you how it became what it is.

ψ/memory/{contexts,retrospectives,learnings}

Anatomy · 01

The skill file.

---
name: ccc
description: Create context issue and compact
  conversation. Use when user says "ccc",
  "save context", "context dump", or before
  switching tasks.
allowed-tools:
  - Bash
  - Read
  - Write
---

# /ccc — Create Context & Compact

## Step 0: Timestamp
date "+🕐 %H:%M (%A %d %B %Y)"

## Step 1: Gather Information
git status --porcelain
git log --oneline -5
git branch --show-current

Frontmatter is the router

The description isn't documentation — it's the matcher. It names the exact phrases that should summon this skill, which is why they read like transcripts of real requests rather than a summary.

Tools are declared, not assumed

allowed-tools scopes what the skill may reach for. A bookkeeping skill gets Bash and Write; a personality switch does not need them.

Steps are numbered and literal

Real commands, in order, with the actual flags. The file is executable by reading — no framework parses it, no registry indexes it.

It ends by handing off

Most skills close by loading a resonance file, so the steps are performed in a voice rather than in the default one.

| Ken Thompson  | Think like OS      |

## My Values
1. Correctness  2. Simplicity
3. Honesty      4. Thoroughness

## Resonance Log
### 2026-04-18 — Born
- Mission: งานหลุดไม่ได้
- First deployment: bug review

Identity, in the first person

Every heading is "My" or "I" — Who I Am, My Values, My Voice. The file is written as the Oracle, not about it, which is what makes it loadable as a stance.

DNA as a table, not an adjective

Each named master is paired with the specific trait inherited. "Rob Pike → simplicity is power" is actionable in a way that "writes clean code" never is.

Values are ranked

A numbered list, so conflicts resolve. Jimmy puts correctness above simplicity — that ordering decides what happens when the two disagree.

The log is append-only

Dated entries recording what shaped this Oracle. Nothing is rewritten; the history is the character.

What to take away

Seven patterns and one rule.

01

Skill ≠ Resonance

Mechanics and identity live in different files. Utility skills can stand alone; personality skills bind the two tightly.

02

DNA distillation

Name real masters and the specific trait taken from each. It gives a persona an anchor you can argue with.

03

Voice as code

Pronouns, sentence endings, emoji policy, sample lines. Concrete enough to apply the same way twice.

04

Append-only log

Dated entries for every change to an identity. Nothing is rewritten — the history is part of the character.

05

Skill = Markdown file

Nothing parses it, nothing compiles it. The file system is the database, and any file copies to another machine intact.

06

Family ≠ tools

A specialist task gets both a workflow and a person. The skill is the wrapper; the resonance is the who.

07

Family connections

Each resonance links to the others it works with, so responsibilities and handoffs are written down.

Rule

Spawn, don't roleplay

"ถ้าจะ summon agent — spawn จริงผ่าน Agent tool ห้าม simulate ใน chat." An Oracle is a real invocation, not a performance.

Pattern 04 · in practice

Nothing is deleted.

Elza's resonance log is the clearest example in the archive. Four dated entries across three months, none of them edited away — including the awkward ones. You can read the exact session where she was asked to be sweeter, and the exact day a programming mode was bolted on top.

The result is an identity with provenance. When an Oracle behaves a certain way, the log says when that started and who asked for it, which turns "why does it talk like this" into a question with an answer.

The honest version, too. พี่เปิ้ง's log records the human's blunt feedback — "บอกหลายรอบไม่เข้าใจ" — and the lesson drawn from it: decide, don't ask twice. Keeping the criticism is what makes the log worth reading.

Read it critically

What the archive doesn't do.

These caveats are the archive's own — its reading notes flag them before anyone else can. That self-criticism is a feature worth copying along with the file format.

Named influences are intent, not credentials

Listing Ken Thompson describes how the persona is meant to behave. It does not make the agent an expert, and it does not mean those people endorsed or reviewed anything here.

Family connections describe, they don't execute

The links between Elza, Jimmy and the rest record who is responsible for what. Nothing in a Markdown file actually routes a task to another agent.

The archive breaks its own rule

The heuristic says summon real agents, never simulate in chat — but the personality skills are written as instructions to switch persona in-session. Intent and implementation disagree, and the archive says so.

Steps still depend on their environment

A skill is only executable where its tools and paths exist. Copying peng-bookkeeping to another machine gets you the tax knowledge, not the working pipeline.

This copy is anonymized

Names, companies, vendors, bank and tax identifiers and every financial figure were replaced with placeholders. Public figures cited as design influences were kept as written.

Where to begin

Two files is the whole barrier to entry.

STEP 01

Write the resonance first

Name it. Give it a born date, a role, and five to ten real practitioners with the specific trait taken from each. Then write four sample sentences in its voice.

STEP 02

Write the skill around it

Frontmatter with the phrases that should summon it. Numbered steps with real commands. Close by loading the resonance file.

.claude/skills/{name}/SKILL.md

STEP 03

Append, never overwrite

Every time the identity shifts, add a dated entry saying what changed and who asked. Keep the unflattering ones — those are the entries that make the log useful.
