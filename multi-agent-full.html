A multi-agent run used roughly 15× the tokens of a single chat; a single agent alone used ~4×. On their BrowseComp eval, token usage explained 80% of the variance in outcome. The orchestrator-worker system beat single-agent Opus 4 by 90.2% — but most of that was buying more thinking, not smarter coordination.

รันแบบหลายเอเจนต์กิน token ประมาณ 15 เท่าของแชตเดี่ยว ส่วนเอเจนต์เดียวกินราว 4 เท่า บน eval BrowseComp จำนวน token อธิบายความต่างของผลลัพธ์ได้ 80% ระบบ orchestrator-worker ชนะ Opus 4 เดี่ยวไป 90.2% แต่ส่วนใหญ่คือซื้อการคิดเพิ่ม ไม่ใช่ประสานงานเก่งขึ้น

There are exactly three reasons to pay that price.

เหตุผลที่คุ้มจะจ่ายราคานั้น มีอยู่สามข้อเท่านั้น

01

Context protection

กันบริบทไม่ให้ล้น

The work needs more context than one window holds, or noisy sub-work would pollute the main thread.

งานต้องใช้บริบทมากกว่าที่หน้าต่างเดียวรับไหว หรืองานย่อยที่รกจะมาเลอะ thread หลัก

02

Parallelization

ทำพร้อมกันได้

The subtasks are genuinely independent — breadth-first search, not a chain of dependent decisions.

งานย่อยแยกขาดจากกันจริง เป็นการค้นแบบกว้าง ไม่ใช่ห่วงโซ่การตัดสินใจที่พึ่งกัน

03

Specialization

ต้องการความเชี่ยวชาญเฉพาะ

A different model, tool set, or persona does one slice measurably better than the generalist.

โมเดล เครื่องมือ หรือบุคลิกที่ต่างออกไป ทำงานชิ้นนั้นได้ดีกว่าตัวทั่วไปแบบวัดได้

The test isn't the problem type. It's: can the context be truly isolated? เกณฑ์ไม่ใช่ประเภทของปัญหา แต่คือ แยกบริบทออกจากกันได้จริงไหม

Cognition's counter-essay lands on the same place from the other side: agents that don't see each other's work make conflicting implicit decisions — their example is one subagent drawing a Mario background while another draws a mismatched bird.

บทความฝั่ง Cognition ที่เถียงกลับ ก็มาจบที่จุดเดียวกันจากอีกด้าน คือเอเจนต์ที่ไม่เห็นงานกัน จะตัดสินใจโดยนัยขัดกันเอง ตัวอย่างของเขาคือตัวหนึ่งวาดฉากหลังแบบ Mario อีกตัววาดนกที่ไม่เข้ากันเลย

In one slide

Single agent by default. Spawn for three reasons. Check the frame first.

Stay single whenอยู่เดี่ยวเมื่อ
  • it's coding with shared mutable state
  • each step depends on the last step's live decision
  • the budget can't absorb 3–15× tokens
  • you haven't checked the premise yet
  • เป็นงานโค้ดที่มี state ร่วมแล้วเปลี่ยนได้
  • แต่ละขั้นพึ่งการตัดสินใจสด ๆ ของขั้นก่อน
  • งบรับ token 3–15 เท่าไม่ไหว
  • ยังไม่ได้ตรวจโจทย์เลย
Fan out whenกระจายเมื่อ
  • the context can be truly isolated
  • subtasks are independent — breadth, not chain
  • verification is cheap and objective (tests, voting)
  • you've run one worker first, and it came back
  • แยกบริบทออกจากกันได้จริง
  • งานย่อยเป็นอิสระ กว้าง ไม่ใช่โซ่
  • ตรวจสอบได้ถูกและเป็นกลาง (test, โหวต)
  • รันหนึ่งตัวไปก่อนแล้ว และมันกลับมา
